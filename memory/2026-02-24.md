## PR #25104 - Moonshot Context Cache (submitted)

- **Implementation**: `src/agents/moonshot-cache.ts` (325 lines)
- **Integration**: `src/agents/pi-embedded-runner/extra-params.ts` (+20 lines)
- **Unit tests**: `src/agents/moonshot-cache.test.ts` (11 tests passing)
- **PR**: https://github.com/openclaw/openclaw/pull/25104

### Key Architecture Decisions
- **sessionKey-based caching**: One cache entry per session, invalidated on content hash change
- **Async IIFE pattern**: Resolve cache BEFORE streaming starts (fixes race condition)
- **FIFO eviction**: `MAX_CACHE_SIZE=1000` prevents memory leak
- **Model name mapping**: `toCacheModelName()` converts `moonshot-v1-32k` → `moonshot-v1`

### Bug Fixes During Review
1. **Async race**: Changed to async IIFE that resolves cache before returning stream
2. **Memory leak**: Added max cache size with FIFO eviction
3. **Stale entry**: Clear local entry before remote deletion
4. **sessionKey undefined**: Greptile caught `options?.sessionKey` always undefined (not in `SimpleStreamOptions`)
   - Fix: Capture sessionKey via closure at wrapper-creation time (commit `2676df357`)

### Testing Lesson
- Direct curl to Moonshot API validated API behavior but NOT OpenClaw integration
- Greptile correctly found the sessionKey bug that manual testing missed
- Next: Write proper e2e test through OpenClaw wrapper chain
